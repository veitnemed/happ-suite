# ЭТАП 06 — правдивый статус и устойчивость

Переработай `src/health.py` так, чтобы зелёный индикатор означал нужное пользователю конечное состояние, а не просто TCP-порт 127.0.0.1. Предусмотри отдельные сигналы:
- процесс HAPP жив;
- локальный прокси отвечает;
- системный туннель/маршрут направляет контрольный трафик как запланировано;
- HTTPS/DNS из тестового системного клиента проходят (учитывай, что часть проверок может обойти туннель через собственный прокси);
- AG Unlocker активен и проверка Antigravity проходит.

Не сравнивай один внешний IP с предопределённым адресом VPN-сервера — адрес выхода может отличаться. Не трактуй отсутствие доступа к аккаунту Google как доказательство поломки VPN. Устанавливай отдельные timeout, retries, backoff и hysteresis. Не запускать бесконечный switch по одному потерянному пакету, не проводить тяжёлые тесты когда OFF. Отдельно проверять после sleep/resume.

При ошибке не удаляй все маршруты, DNS или proxy settings. Возвращай только собственные изменения. Пользовательский HAPP и AG Unlocker, уже работавшие до старта Suite, должны остаться принадлежащими пользователю. Удостоверяйся, что abort в середине startup не оставляет «полуподключение». Добавь подробные локальные логи с маскированием ссылок подписки.

Тесты изоляции проверок, тайм-аутов, корректного статус-индикатора, rollback и отсутствие агрессивной петли восстановления. Реальные сетевые тесты проводить только по правилам этапа 07.
