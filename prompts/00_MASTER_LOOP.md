# ГЛАВНЫЙ ПРОМПТ — автономный цикл разработки Happ Suite

Ты Codex в репозитории `veitnemed/happ-suite` (Windows 10/11 x64, Python-проект). Читай этот файл и этапы 01–09 по порядку. Изучай **текущие файлы репозитория**, а не считай устаревший README доказательством реализации. Не сменяй VPN-движок на sing-box/mihomo/happ-cli без отдельного обоснования: MVP управляет установленным HAPP и AG Unlocker.

## Результат

Одна назначаемая глобальная клавиша (по умолчанию F8) переключает **единый сценарий**:
- OFF → в фоне поднимается существующий HAPP VPN, запускается/проверяется установленный AG Unlocker, подтверждается работоспособность пути к Antigravity → READY;
- READY/DEGRADED → по повторному нажатию отменяется/завершается только то, чем владеет Happ Suite, VPN отключается штатно, изменённые настройки возвращаются → OFF;
- интерфейсом служит иконка в трее: серый OFF, жёлтый STARTING/STOPPING/RECOVERING, зелёный подтверждённый READY, красный ERROR; при частичном состоянии tooltip явно указывает неисправный компонент;
- никакого CMD/PowerShell и нежелательного появления окон HAPP или AG Unlocker при штатном переключении. Если установленная версия не умеет запускаться по-настоящему без окна — документируй и минимизируй появление, не обещай абсолютный нулевой flash без теста;
- нет жёсткой привязки к Kitty VPN и локальным IP/ID разработчика.

## Цикл «делай пока не получится»

Для КАЖДОГО этапа:
1. Прочитай условия этапа и соответствующий реальный код.
2. Запиши в `prompts_progress/STATUS.md` цель, текущее состояние, проверяемую гипотезу, ограничения среды и следующий тест.
3. Сделай **минимальное осмысленное изменение**.
4. Выполни доступные безопасные тесты (lint/unit/mock/integration по возможностям), зафиксируй команду, exit code, журнал, наблюдаемый результат.
5. Если не работает — локализуй точку отказа, меняй **одну существенную причину за раз**, повторяй тест. После 3 безрезультатных вариаций одной гипотезы останови этот подход, пересмотри гипотезы или найди документацию/исходники, затем продолжи. Не зацикливайся на случайном изменении маршрутов.
6. Повторяй безопасный цикл, пока критерии этапа не выполнены. При непроверяемом внешнем ограничении честно запиши BLOCKED и точное необходимое действие пользователя; переходить дальше можно только для независимых задач.
7. По завершении этапа обнови `STATUS.md`, `CHANGELOG_DEV.md` и `09_ACCEPTANCE_MATRIX.md`: PASS / FAIL / BLOCKED / NOT_TESTED с доказательством.

**Не заявляй «работает», когда есть только компиляция/запуск процесса. Не фабрикуй результаты Windows-испытаний в Linux или из чтения кода.** Если ты работаешь не на ПК пользователя, тесты реальных EXE отмечай BLOCKED.

## Обязательные границы безопасности

- Без согласия владельца НЕ отключай действующий VPN, не меняй default routes, DNS, firewall, сетевые адаптеры, службы, автозапуск или UAC; не закрывай произвольный Happ.exe/ag_dns.exe. Допускаются чтение системы, dry-run, изолированные unit-тесты и редактирование репозитория.
- Для первого реального переключения создай и проверь независимый recovery-механизм по этапу 07 либо запроси явное разрешение на испытание с независимым доступом к ПК. Не маскируй риск фразой «потеряем интернет на 5 секунд».
- Не удаляй чужие маршруты/настройки, не делай `netsh winsock reset` и не отключай чужие приложения.
- Перед изменением существующего кода сохрани рабочее состояние через git и опиши изменения; не коммить секреты и реальные ссылки подписки.
- Никогда не заменяй недостающую проверку постоянным sleep. Тайм-аут + наблюдаемый статус + восстановление.
- Не запускай бесконечные внешние запросы и не расходуй бесконтрольно время на флаки-тест; объясни реальный блокер.

## Как действовать с пользовательским подтверждением

Один раз, ПОСЛЕ успешного dry-run и проверки rollback, предложи точный сценарий реального теста: что изменится, сколько ждать, как вручную восстановить сеть и как подтвердить запуск. Не притворяйся, что можешь бесшовно продолжать прерванную облачную сессию Codex. Запрос может оборваться; независимый скрипт продолжится и запишет лог, а пользователь затем возобновит Codex.
