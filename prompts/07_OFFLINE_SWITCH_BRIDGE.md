# ЭТАП 07 — независимая от Codex среда сетевых экспериментов

Причина: прежние тесты happ-cli→SOCKS5→tun2socks→Wintun проходили, когда действующий HAPP сам держал TUN и default routes. Управляющая сессия Codex могла оборваться при отключении HAPP, поэтому эксперименты обрастали конфликтующими /32 маршрутами. Не повторять это без изоляции.

Создай `experiments/vpn-bridge/` с `install.ps1`, `switch.ps1`, `restore.ps1`, `watchdog.ps1`, `status.ps1`, `README.md`. Механизм — автономное локальное задание через Windows Task Scheduler либо сравнимый независимый исполнитель, который живёт после смерти терминала/обрыва интернета. `switch` передаёт ID и немедленно возвращает управление; процесс пишет JSON-журнал и heartbeat на диск.

Ключевые требования:
- Предварительный snapshot: состояние HAPP, конкретный сервер/профиль, адаптеры, IPv4/IPv6 маршруты, DNS, ownership, отметка успешного внешнего запроса; не писать токены в логи.
- Подготовить отдельный watchdog ДО изменения сети; watchdog с независимым тайм-аутом, не один finally основного процесса.
- Заданная пользователем пауза 5 секунд после отключения; ожидание нового соединения до разумного конфигурируемого предела; по fail/timeout попытка восстановить старое рабочее подключение.
- Не обещать восстановление за 5 секунд; физическая сеть/сервер могут быть недоступны.
- Менять только свои настройки. Не `taskkill /im Happ.exe /f`, не общий netsh reset, не выключать сторонние VPN/службы. Не запускать два TUN одновременно как «проверку».
- Не обещать автоматического возобновления самого облачного запроса Codex: результат сохраняется, после возвращения сети пользователь/агент читают лог и продолжают.

Тестовая лестница (строго):
1. DRY RUN, только файл/heartbeat, никаких сетевых изменений.
2. Закрыть родительский PowerShell и убедиться, что задача завершилась и статус читается.
3. Искусственно зависший тестовый worker → watchdog должен зафиксировать timeout, не трогая сеть.
4. Read-only snapshot работающего HAPP.
5. Подготовить сценарий и инструкции ручного восстановления.
6. **ОСТАНОВИТЬСЯ и запросить отдельное согласие на реальное отключение VPN** с указанием возможного обрыва Codex. Только после подтверждения проводить одно контролируемое отключение.

Если Task Scheduler/права недоступны, пометить BLOCKED и дать конкретную команду пользователю, не фабриковать успех. Не трать время на TUN-разработку до выполнения этой лестницы.
