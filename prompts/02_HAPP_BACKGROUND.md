# ЭТАП 02 — HAPP: управляемый и тихий запуск

Реализуй/отрефакторь адаптер HAPP с понятным контрактом: `get_status()`, `start(server=None)`, `disconnect()`, `stop_owned()`, `get_servers()` (если есть подтверждённая возможность). Он НЕ должен зависеть от GUI Happ Suite.

Требования:
1. Сначала проверь доступные у установленного HAPP штатные варианты автозапуска, сворачивания и управления подключением. Если реальный headless недоступен, честно используй GUI скрытым/свёрнутым способом как промежуточный MVP. `ShowWindow` после появления окна — не гарантия отсутствия flash.
2. Не используй `proc.kill()` по одному имени приложения. Храни созданный PID/handle и отличай «наш HAPP» от уже запущенного владельцем. Для отключения соединения предпочитай официальный механизм, не насильственное завершение EXE. При отсутствии безопасного способа — BLOCKED для этого подпункта и точная альтернатива.
3. Не перезаписывай безусловно `lastServer` и другие значения реестра; сохраняй/восстанавливай изменённые ключи, валидируй ID и версию клиента.
4. Повторный start не создаёт второй HAPP и не пытается поднимать два TUN. Наличие другого системного VPN обнаруживается и показывается как конфликт без автоматического отключения.
5. Фиксируй состояния OFF, STARTING, CONNECTED, DEGRADED, ERROR, STOPPING отдельно от списка запущенных процессов. Не считать открытый порт доказательством VPN.
6. Не запускать CMD/PowerShell-окна и не забирать фокус при штатной работе. Различай параметры `CREATE_NO_WINDOW`, `STARTUPINFO` и особенности GUI-процессов, проверяй на Windows.

Тесты: unit/mock переходов, повторный start, уже запущенный чужой HAPP, отсутствующий EXE, сбой startup/timeout, отмена во время старта, возврат ранее изменённых настроек. Реальную смену соединения пока не запускай без согласования этапа 07. Обнови STATUS.
